SolidWorks 参数化批量建模

把「改个尺寸、重新建一遍、导个图、量一下体积对不对」这套重复动作交给脚本： params.csv 里一行就是一个零件，跑一遍， SLDPRT、PNG、核对报告全都出来了。

流程

读 params.csv → 逐行建模 → 存 SLDPRT + PNG → 用解析公式核对体积 → 写 report.csv

零件族是「L × W × T 的矩形板，四角各一个 Ø hole_dia 的通孔，孔心距两条邻边各 margin」。 输入长这样：

nameLWThole_diamargin
plate_A1006010812
plate_B15080121015
plate_C80806610

怎么确认建对了

建模脚本最怕的是「跑完没报错，但零件是错的」。所以每建完一个， 都从模型里读出实际体积，和解析公式算出来的理论值比： 

理论体积 = L*W*T - 4 * pi * (hole_dia/2)^2 * T

逐行写进 report.csv，对不上就是 FAIL：

namevolume_mm³expected_mm³err_pctmass_gverdict
plate_A57989.38157989.3810.057.989PASS
plate_B140230.089140230.0890.0140.230PASS
plate_C37721.41637721.4160.037.721PASS

踩过的坑

SolidWorks 的 COM 接口是给 VBA 设计的，用 Python 晚绑定调它， 文档上写得通顺的地方实际全是雷。基础层里每一条注释都是实测换来的：

SaveAs3 的返回值不可信

它说保存成功不一定真落盘了。判断成败只能去看文件在不在硬盘上。

Callout 参数不能传 None

必须传一个 VT_DISPATCH 的空指针。传 Python 的 None 会直接炸。

中文版的默认模板路径指向一个不存在的文件

默认模板偏好指向 零件.prtdot，而这个文件并不在那儿。只能自己回退扫描去找。

版本之间接口会消失

CreateMassProperty 在 SW2023 上已经不能用了，得改走 Extension.GetMassProperties2。另外 RevisionNumber、GetTitle 这些在晚绑定下是属性不是方法，当方法调就报错。

单位这件事单独说

SolidWorks API 内部一律用米，而画图的人脑子里全是毫米。 与其每次调用都换算、每次都可能忘，不如定死一条边界： 基础层对外的接口全部收发毫米，米只存在于基础层内部，转换只在边界上做一次。
